关于虚表

一、什么是虚表

核心定义 虚表（Virtual Table，简称 VTable）是 C++ 实现动态绑定（多态）的底层核心机制，由编译器自动生成和维护，无需手动编写。

  • 本质：一个常量指针数组，数组中存储的是当前类所有虚函数的内存地址；
  • 虚表指针（vptr）：编译器会为包含虚函数的类，自动在对象中插入一个隐藏的指针，指向类的虚表；
  • 绑定特性：虚表解决了编译期无法确定函数调用目标的问题，将函数调用决议推迟到运行期（动态绑定）。

核心组成

  1. 虚函数表（VTable）：类级别，所有同类对象共享同一张虚表，存储虚函数地址；
  2. 虚表指针（vptr）：对象级别，每个对象都拥有，指向所属类的虚表。

二、虚表的生成与存储

虚表在编译期由编译器完整生成，通常放置在只读数据段（如 Linux 下的 .rodata），因此程序运行期间不会被意外修改。对于含有虚函数的类 C，编译器会：

  • 为 C 创建一张虚表，表中按虚函数声明顺序（考虑继承）依次存放各虚函数的入口地址。
  • 在 C 的对象布局中隐式插入一个 vptr（在多数实现中位于对象的起始位置），该指针会在对象构造时被正确初始化，指向 C 的虚表。 示例代码：
#include <iostream>

class Base {
public:
    virtual void f() { std::cout << "Base::f" << std::endl; }
    virtual void g() { std::cout << "Base::g" << std::endl; }
};

// 辅助函数：打印对象前8字节（即vptr的值，64位系统）
void print_vptr(void* obj) {
    // 对象起始地址存放的就是vptr
    uintptr_t* vptr = reinterpret_cast<uintptr_t*>(obj);
    std::cout << "vptr: 0x" << std::hex << *vptr << std::dec << std::endl;
}

int main() {
    Base b1, b2;
    print_vptr(&b1);  // b1的vptr
    print_vptr(&b2);  // b2的vptr，应当与b1相同（指向同一张Base虚表）
}

运行结果（不同地址仅作示例）：

vptr: 0x55d4a3e0bd38
vptr: 0x55d4a3e0bd38

可见，所有 Base 对象共享同一个虚表地址。

三、构造与析构过程中的 vptr

虚表指针在构造和析构函数中会随着继承链条逐步切换，以保证在基类构造函数中调用的虚函数不会意外落入尚未初始化完全的派生类版本。

  1. 构造阶段：先调用基类构造函数。进入基类构造函数体之前，对象的 vptr 会被设置为该基类的虚表；基类构造完毕后，再沿继承层次向下，依次更新 vptr 为各个派生类的虚表，直到最终类构造函数执行完成。因此，在构造函数中调用虚函数不具备多态行为，只会调用当前构造层次对应的版本。
  2. 析构阶段：过程与构造相反，从最终析构函数开始，vptr 逐级向基类回退，确保在析构函数中调用虚函数不会访问已销毁的派生类资源。 示例代码：
#include <iostream>

class Base {
public:
    Base() { 
        std::cout << "Base::Base() -> "; 
        show();  // 构造中调用虚函数
    }
    virtual ~Base() {
        std::cout << "Base::~Base() -> ";
        show();
    }
    virtual void show() { std::cout << "Base::show" << std::endl; }
};

class Derived : public Base {
public:
    Derived() { 
        std::cout << "Derived::Derived() -> "; 
        show(); 
    }
    ~Derived() {
        std::cout << "Derived::~Derived() -> ";
        show();
    }
    void show() override { std::cout << "Derived::show" << std::endl; }
};

int main() {
    Derived d;  
    // 输出将展示构造函数中虚函数没有多态行为
}

输出示例：

Base::Base() -> Base::show
Derived::Derived() -> Derived::show
Derived::~Derived() -> Derived::show
Base::~Base() -> Base::show

在 Base 构造函数内，虽然对象最终是 Derived 类型，但此时 vptr 仍指向 Base 的虚表，因此调用的是 Base::show。析构过程对称，Base 析构时 vptr 已回退到 Base 虚表。

四、单继承中的虚表布局

单继承体系下，派生类会“拷贝”一份基类的虚表结构，并用自身的重写版本替换对应的函数地址。如果派生类新增了虚函数，这些新函数的地址会被依次追加在虚表末尾。

class Base {
public:
    virtual void f() { std::cout << "Base::f" << std::endl; }
    virtual void g() { std::cout << "Base::g" << std::endl; }
};

class Derived : public Base {
public:
    void f() override { std::cout << "Derived::f" << std::endl; }
    virtual void h() { std::cout << "Derived::h" << std::endl; }
};

可以通过模拟虚表结构来观察布局：

void inspect_vtable() {
    using FuncPtr = void(*)();
    Derived d;
    uintptr_t* vptr = reinterpret_cast<uintptr_t*>(&d);
    uintptr_t* vtable = reinterpret_cast<uintptr_t*>(*vptr);

    // 假设虚表第一个条目是type_info指针（见后文RTTI），我们跳过它
    // 在Itanium ABI下，虚函数从vtable[0]或vtable[1]开始取决于实现，此处直接展示地址
    FuncPtr* funcs = reinterpret_cast<FuncPtr*>(vtable + 1); // 可能需要调整偏移

    std::cout << "Derived vtable:" << std::endl;
    for (int i = 0; i < 3; ++i) {
        printf("  [%d]: %p\n", i, funcs[i]);
    }
}

典型输出中，funcs[0] 是 Derived::f，funcs[1] 是 Base::g，funcs[2] 是 Derived::h，验证了覆盖与追加的布局规则。 当执行 Base* ptr = new Derived(); ptr->f(); 时，运行时：

  • 通过 ptr 取得 vptr；
  • 在编译期已知 f 在虚表中的索引（此处为0），直接按偏移量取出函数指针并调用。

五、多重继承下的虚表与 this 调整

当派生类同时继承多个含有虚函数的基类时，对象内部将包含多个 vptr，分别指向不同基类子对象对应的虚表。 以如下代码为例：

class Base1 {
public:
    virtual void f() { std::cout << "Base1::f" << std::endl; }
};
class Base2 {
public:
    virtual void g() { std::cout << "Base2::g" << std::endl; }
};
class Derived : public Base1, public Base2 {
public:
    void f() override { std::cout << "Derived::f" << std::endl; }
    void g() override { std::cout << "Derived::g" << std::endl; }
    virtual void h() { std::cout << "Derived::h" << std::endl; }
};

对象内存布局（64位）：

Derived:
  vptr1 (Base1子对象) -> 主虚表
  Base1 成员（如果有）
  vptr2 (Base2子对象) -> 次虚表
  Base2 成员（如果有）
  Derived 自身成员

验证双重vptr和this调整的thunk：

void demonstrate_thunk() {
    Derived d;
    Base2* p2 = &d;  // p2 指向Derived内部的Base2子对象

    // 打印 p2 的地址与 d 的地址，观察偏移
    printf("Address of d:   %p\n", &d);
    printf("Address of p2:  %p\n", p2);
    // 差值应为 sizeof(Base1)（若有成员变量）
}

输出（假设无成员变量，仅vptr，64位下可能差8字节）：

Address of d:   0x7ffee5c3a0b8
Address of p2:  0x7ffee5c3a0c0   (相差8字节，即vptr1的大小)

当调用 p2->g(); 时，g 在次虚表中的条目实际不是直接指向 Derived::g，而是一个 thunk，它会将 this 减去适当偏移，再跳转到 Derived::g 的实现。可以通过查看虚表中函数指针的地址（通常与普通成员函数地址不同）来感知 thunk 的存在，但具体细节依赖编译器 ABI。

六、虚继承与虚表

虚继承用于解决菱形继承问题，其底层往往借助额外的虚基类表或虚表中的负偏移条目来定位虚基类子对象。

class Base {
public:
    int data;
    virtual void f() {}
};

class Derived1 : virtual public Base {
public:
    void f() override {}
};

class Derived2 : virtual public Base {
public:
    void f() override {}
};

class Final : public Derived1, public Derived2 {
public:
    void f() override {}
};

在典型的虚继承布局下，Final 对象中会同时包含 Derived1 和 Derived2 的子对象，但它们共享同一个 Base 子对象。每个虚派生类（Derived1、Derived2）的虚表或单独的表（如 vbtable）会存储一个偏移量，用于在运行时找到 Base 的位置。可以通过打印对象地址和基类指针的转换来验证：

Final obj;
Base* pb = &obj;  // pb 自动指向唯一的Base子对象
Derived1* pd1 = &obj;
Derived2* pd2 = &obj;

printf("Final object: %p\n", &obj);
printf("Derived1*:     %p\n", pd1);
printf("Derived2*:     %p\n", pd2);
printf("Base*:         %p\n", pb);
// 地址各不相同，展示了虚继承的复杂布局

输出示例（地址示意）：

Final object: 0x7ffc108b0a10
Derived1*:     0x7ffc108b0a10
Derived2*:     0x7ffc108b0a20
Base*:         0x7ffc108b0a30

Base 子对象在对象尾部的现象，体现了通过虚表间接定位虚基类的机制。

七、虚表与运行时类型识别（RTTI）

在主流 C++ ABI 中，虚表第一个函数条目之前（如 vtable[-1]）通常存放着 type_info 对象的指针，供 dynamic_cast 和 typeid 使用。 演示 typeid 和 dynamic_cast 的工作：

#include <typeinfo>
#include <iostream>

class Base {
public:
    virtual ~Base() {} // 必须有虚函数才有RTTI
};

class Derived : public Base {};

int main() {
    Base* pb = new Derived();

    // typeid 返回多态对象的动态类型
    std::cout << typeid(*pb).name() << std::endl; // 可能输出 "7Derived" (gcc)

    // dynamic_cast 安全向下转型
    Derived* pd = dynamic_cast<Derived*>(pb);
    if (pd) {
        std::cout << "dynamic_cast succeeded" << std::endl;
    }

    // 非多态类型无法 dynamic_cast
    // class NonPoly {}; NonPoly* np = new NonPoly;
    // dynamic_cast<...>(np); // 编译错误
    delete pb;
}

运行时，dynamic_cast 通过 vptr 找到虚表，再访问 type_info，与目标类型比对来实现安全检查。

八、虚函数调用的底层细节与性能

调用 ptr->func() 通常需要： 读取 ptr 指向对象的 vptr（一次内存访问）。 在虚表中按已知索引获取函数地址（第二次内存访问）。 间接调用该函数。 与直接调用相比，多了两次解引用，且编译器通常无法内联。可以通过简单测试感知开销：

#include <chrono>
#include <iostream>

class Interface {
public:
    virtual int call() = 0;
};

class Impl : public Interface {
public:
    int call() override { return 42; }
};

void direct_call() {
    Impl obj;
    volatile int x;
    for (int i = 0; i < 100000000; ++i) {
        x = obj.call(); // 可能被内联优化
    }
}

void virtual_call() {
    Interface* obj = new Impl();
    volatile int x;
    for (int i = 0; i < 100000000; ++i) {
        x = obj->call(); // 虚调用
    }
    delete obj;
}
// 运行比较时间，直接调用通常更快

现代编译器在能静态推导出对象具体类型时，会进行“去虚化”，将虚调用转为直接调用。但在无法推导的场景（如通过外部传递的指针），开销仍存。

九、安全性考量与常见误区

vptr 被破坏：若对象发生缓冲区溢出，vptr 可能被篡改，导致调用虚函数时跳转到任意地址。 纯虚函数调用：构造或析构中间接调用纯虚函数会导致程序终止。 示例：模拟纯虚函数调用错误：

class Abstract {
public:
    Abstract() { /* 不小心调用了纯虚函数 */ }
    virtual void pure() = 0;
    void call_pure() { pure(); }
};

class Concrete : public Abstract {
public:
    void pure() override {}
};

int main() {
    Concrete c; // 若Abstract构造函数中调用了call_pure，会崩溃
    // 下面演示析构时风险：
    // Abstract* pa = new Concrete;
    // delete pa; // 抽象基类析构函数若调用纯虚函数同样危险
}

正确的设计应避免在构造/析构中调用虚函数，尤其是纯虚函数。

十、总结

虚表是 C++ 多态的灵魂，它将接口与实现分离，在保持零成本抽象（仅在使用虚函数时才引入开销）的前提下，为大规模面向对象设计提供了坚实的底层支撑。理解虚表在单继承、多继承、虚继承中的布局变化，以及构造/析构期间 vptr 的动态切换，不仅有助于编写更高效、更安全的 C++ 代码，也有助于从根本上排查那些与多态相关的诡异运行时问题。
